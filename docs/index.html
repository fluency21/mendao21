从一张显卡到医生工作台

# 从一张显卡到医生工作台

> 专题 · 把"算力、芯片、买卡、部署"这串词，用一个你天天打交道的场景走一遍：一个糖尿病专病模型，是怎么出现在社区医院王医生的工作台上的。读完这篇，DeepSeek 那条新闻里的"三件套"（模型、框架、算力）就都有了具体的脸。

先说说显卡：为什么全世界都在抢这玩意儿

一个大模型，拆开看其实什么都不是，就是一大堆数字。V4 Pro 有 1.6 万亿个，行话叫参数。这些数字本身躺在硬盘里毫无用处，得"算"起来才有智能。

问题是怎么算。模型每回答一句话，背后要做上万亿次乘法。这种活有个特点：单次数值计算极其简单，但量大到吓人。这时候 CPU 和 GPU 的差别就出来了。CPU 像一位数学教授，能解微积分，但一次只能解一道。GPU 像一万名小学生，每人只会加减乘除，但能同时动笔。训练大模型这种活，交给教授是暴殄天物，小学生军团才是真正的主力。所以搞 AI 的公司抢的不是电脑，是显卡，行话叫"卡"。

一张卡还不够。这就引出第二个词：显存。模型的 1.6 万亿个参数，必须全部摊开在显卡的工作台上才能开工，这个工作台就是显存。哪怕做了压缩，V4 Pro 这种块头也要 1 个多 TB 的显存，而一张顶级卡的显存只有 80GB 上下。怎么办？把几十张、上百张卡用高速线路捆在一起，当成一台机器用。这就是新闻里"十万卡级算力池"的意思：十万张显卡捆成的超级机器。

接着是"买卡"。最好的卡在英伟达手里，但美国管制，H100 这类顶级卡不卖中国。所以才有了国产替代这条线：华为的昇腾、寒武纪这些卡顶上来。可光换卡不行，模型原来是照着英伟达的脾气写的，换国产卡要重新适配调教，这就是新闻里"已适配昇腾、寒武纪"这行小字的分量。看着不起眼，背后是成年的工程活。

最后是超算互联网。全国各地的超算中心本来就有大量算力，过去主要给气象、物理这些科研用，利用率并不饱和。现在把这些卡连成一张网统一出租，像电网卖电一样卖算力。你可以不买发电机，直接插电用。

算力、芯片、买卡，三个词到这里就连起来了：芯片是干活的工人，买卡是招工人，算力是把工人组织起来按时计酬的劳务市场。

模型的养成：从通才到糖尿病专家

有了卡，模型的成长分三步走，每一步烧的钱和解决的问题完全不同。

第一步叫预训练。让模型把互联网上几乎所有公开文字读一遍，学会" predict 下一个词"。这一步要几千张卡连跑几个月，光电费就是几千万。跑出来的是个通才，天文地理都能聊，但哪科都不精，也不懂规矩，你问病情它可能给你背教科书。

第二步叫后训练，相当于毕业后的岗前培训。不改大脑结构，只教工作方法：怎么按步骤干活，怎么调用工具，答不上来别瞎编。还记得那条新闻吗，V4 Pro 架构和参数一个数字都没动，只靠后训练改进，Agent 考分从 12.8 涨到 62.7。岗前培训的质量，越来越比学历本身重要。

第三步才是医院关心的：专病化，行话叫微调。拿糖尿病的诊疗指南、脱敏后的真实病历，让这个通才再去"内分泌科进修"一遍。出来的就是专病模型。它聊电影可能还是外行，但看糖化血红蛋白的化验单，比住院医老练。

养成了，怎么进医院？两条路，这条路的选择直接影响后面所有的账。

一条路叫调 API：模型住在 DeepSeek 自己的机房里，医院的工作台通过网络把问题发过去，按用量付费，百万 token 几块钱。像用电，不用买发电机，插上插座就有。

另一条叫私有化部署：把模型文件（几百 GB 的一包数字）整个拷进医院自己的服务器，或者超算互联网上租的独立专区。前期要投入几百万买卡建机房，但换来两个 API 给不了的东西：数据不出院，合规上站得住；用量再大也不额外花钱。

医院这种地方，病历数据的敏感性你比我清楚，所以稍上规模的医院大多会认真考虑第二条路。这正是那条新闻里"私有化部署"四个字的含金量，也是国家超算互联网要专门提供这条通道的原因。

还差最后一块：框架。光有个聪明的脑子，躺在服务器里也干不了活。工作台里的模型得能读病历系统、查药品库、按科室的随访流程一步步走。这些"脊髓和手脚"的活，就是 Harness 这类智能体框架干的。它把模型、工具、流程都做成可插拔的模块，医院想加个查药功能，插个插件就行。

王医生敲下回车的那三秒钟

下午三点，社区医院。王医生在 CMC 工作台里敲下一行字：

"65 岁，糖化血红蛋白 8.2，二甲双胍已足量，eGFR 58，要不要加用 SGLT-2 抑制剂？"

回车按下去，接下来三秒里发生的事，比大多数人想的要热闹。

工作台先把这句话和这位患者的病历摘要打成一个包裹。然后包裹里的文字被切成一个个 token，AI 世界的最小字数单位，这句话连同病历，大概几千个。

包裹上路。如果医院走的是私有化，数据顺着内网钻进楼里的机房；如果走 API，就通过专线奔向 DeepSeek 或超算互联网的机房。

到了机房先排队。全院几十位医生可能同时在用，全国同时调用的人更数不清，这就是"并发"。V4 Pro 的并发上限是 500，比 Flash 版的 2500 低不少，因为 Pro 干的是精细活，算力得优先保证质量。排队的拥挤程度还随时间波动，所以 DeepSeek 才要搞峰谷定价：工作时段最贵，夜里便宜。这跟电网峰谷电价是一个道理，算力就是电。

轮到这一单，GPU 集群开工。几千个 token 变成数字向量，流进模型。MoE 架构里那个"分诊台"开始干活：这个问题涉及肾功能和降糖药，路由把它分给药理学和内分泌相关的"专家网络"，1.6 万亿参数里只有 490 亿真正参与计算。这就是它能做到又大又快又便宜的秘诀。

然后你会看到答案一个字一个字往外蹦。这不是界面特效，是模型干活的真实节奏：它每次只算出一个 token，把这个 token 添到末尾再算下一个，几百次循环连成一段话。所谓流式输出，就是把后台这个"逐字蹦"的过程直接直播给你看。

王医生接着追问："那达格列净和恩格列净选哪个？"这一问比第一问便宜得多，为什么？因为模型算第一问时，已经把那几千个 token 的中间结果存在了显存里，行话叫 KV 缓存。第二问复用了这些存底，不用从头再算一遍。这就是定价表上"缓存命中 0.025 元、未命中 3 元"差出 120 倍的由来。一个患者看下来，越聊越便宜。

回答到一半，模型觉得需要核实达格列净在 eGFR 58 时的用药限制。它停下来，通过框架发出一个工具调用，去药品库里查了一圈，拿到结果，接着把话写完。整个中断和接续，王医生在屏幕前毫无察觉。

答案完整呈现在工作台上：建议加用，首选有肾脏获益证据的品种，附剂量和复查提醒。全程三秒上下。这一单如果走 API，几分钱；走私有化，摊下来是几分钱电费。

模型是脑子，负责聪明。框架是神经和手脚，负责把聪明变成动作。算力是心脏和血液，负责让这一切跳得起来。过去这三样分散在不同的供应商手里，医院要自己攒。这次的事，是国家队把三样打包摆在了一个货架上，还顺手解决了"卡被卡脖子"这个最大的隐忧。
